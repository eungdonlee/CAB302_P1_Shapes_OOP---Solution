각주

  1. 커밋 메타데이터. GitHub Emails에 같은 주소 필요. --global=이 PC 사용자 전체. ↑ 본문으로 ↑
  2. 저장소 없으면 clone URL 없음. 과제는 Fork/Collaborator가 흔함. ↑ 본문으로
  3. README 시 원격 첫 커밋. 빈 저장소면 로컬 첫 커밋 후 push. ↑ 본문으로
  4. clone=원격 복사+히스토리+origin. init=현재 폴더에 빈 저장소만(원격은 나중에 remote add+push). 같은 폴더에 둘 다 쓰지 않음. ↑ 본문으로
  5. HTTPS는 Token/Credential/SSH. IntelliJ 브라우저 로그인 가능. ↑ 본문으로
  6. origin=내 fork, upstream=원본. fetch upstream → merge → push origin main. ↑ 본문으로
  7. SSH는 나중에 가능. 공개키만 GitHub. ↑ 본문으로
  8. main 실수 push 거절 → feature→PR만. ↑ 본문으로
  9. pull≈fetch+merge. 최신 main에서 feature 분기. ↑ 본문으로
  10. reset --hard는 로컬 변경 삭제 가능. ↑ 본문으로
  11. 예: feature/add-square. “main만 공식”은 팀 규칙. ↑ 본문으로
  12. Untracked→Staged→Unmodified. Stage=이번 커밋만 고르기. ↑ 본문으로
  13. Commit=로컬. GitHub는 push. ↑ 본문으로
  14. -u 이후 git push만. feature push≠main 변경. ↑ 본문으로
  15. PR=병합 요청+리뷰. 중간 도움 요청에도. ↑ 본문으로
  16. 충돌=같은 줄 동시 수정. 자주 2번으로 예방. ↑ 본문으로
  17. Rebase=히스토리 재작성. 초심자는 merge. ↑ 본문으로
  18. Merge 후 main=새 확정본. Squash/Merge 팀 통일. ↑ 본문으로
  19. .gitignore=저장소별 무시. core.excludesfile=PC 전역. 이미 추적 중이면 ignore만으로 안 빠짐 → git rm --cached. ↑ 본문으로
